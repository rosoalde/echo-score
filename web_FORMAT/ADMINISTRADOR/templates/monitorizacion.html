    Grafana y Prometheus solo escuchan en 127.0.0.1 del servidor (igual que la base de datos y Redis) — no se pueden abrir desde aquí directamente. Las tarjetas de abajo son un resumen rápido que admin-api consulta por la red interna de Docker. Para el detalle completo (histórico, por contenedor, alertas...), abre un túnel SSH desde tu máquina: 
    ssh -L 3000:localhost:3000 -L 9090:localhost:9090 usuario@tu-servidor
    y entra en http://localhost:3000 (Grafana) o http://localhost:9090 (Prometheus).
    No se ha podido consultar Prometheus. Comprueba que los contenedores de monitorización estén levantados (docker compose ps).

    Una vez montado el túnel, estos dashboards de la comunidad de Grafana cubren la mayoría de lo que necesitas — impórtalos por ID desde Grafana (Dashboards → New → Import):

    • Node Exporter Full — ID 1860 (CPU, RAM, disco, red, load, inodes...)
    • Docker / cAdvisor — ID 14282 (CPU/memoria/IO/red por contenedor)
    • PostgreSQL — ID 9628 (conexiones, locks, cache hit, WAL)
    • Redis — ID 763 (memoria, hits/misses, comandos/s)
    • Celery — no hay dashboard "oficial" de comunidad para este exporter, pero ya están confirmadas las métricas reales; monta un panel con celery_worker_up, celery_queue_length, celery_active_process_count, rate(celery_task_succeeded_total[15m]) / rate(celery_task_failed_total[15m]) y histogram_quantile(0.95, sum(rate(celery_task_runtime_bucket[15m])) by (le)) para el p95 de duración

    Para tus dos APIs (fastapi-web / fastapi-admin), como no hay un dashboard "oficial" único, monta uno propio con http_requests_total y http_request_duration_seconds_bucket (así sacas peticiones/s, p95/p99 y errores por endpoint con histogram_quantile).
